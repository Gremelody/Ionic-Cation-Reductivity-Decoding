> 🧪 A chemistry-guided notebook workflow for decoding the reduction propensity of ionic-liquid cations from quantum-chemical descriptors.

---

## ✨ Project Background

This repository supports the cation-design component of a data-driven dual-ion strategy for solid-state batteries. In the associated study, ionic-liquid cations regulate interfacial reduction thermodynamics through their electronic structure, while anions guide the inorganic speciation of the solid-electrolyte interphase.

The released dataset contains 200 ionic-liquid cations represented by 70 physicochemical features. The notebooks connect descriptor selection, predictive modelling, and interpretable analysis to reveal chemical factors associated with cation reductivity.

---

## 🌟 Research Highlights

- **⚛️ Cation-focused design**: links cation electronic characteristics to the reduction chemistry relevant to interphase formation.
- **🧹 Purposeful descriptor refinement**: combines correlation control, Random-Forest/SHAP ranking, and iterative selection to identify a concise informative feature set.
- **🌳 Diverse nonlinear regression**: compares complementary tree-based regressors and synthesizes their predictions with a linear Support Vector Regressor.
- **🔎 Interpretable chemical insight**: consolidates SHAP attributions according to predictive fidelity, providing a robust view of descriptor importance.
- **🔁 Direct workflow continuity**: the feature-engineering output is used directly by the subsequent modelling notebook.

## 🚀 Quick Start

### ① Create the environment

Use Python 3.10 or later:

```bash
python -m venv .venv
```

Activate the environment, then install the released dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
jupyter lab
```

### ② Run the notebooks in sequence

1. Open [`descriptor_selection.ipynb`](./descriptor_selection.ipynb) and run its code cell. It reads `il_lumo_original_data.xlsx` and exports the engineered training table to `feature_engineering_output/`.
2. Open [`ensemble_regression.ipynb`](./ensemble_regression.ipynb) and run the model-search cell followed by the evaluation-and-SHAP cell in the same Jupyter session.

All candidate tree regressors are enabled by default. For a new dataset, retain the candidates that perform well in the benchmark and disable unsuitable candidates consistently in the notebook configuration areas.

## 📐 Data Format

The original Excel file follows one fixed layout:

```text
Molecule | feature_1 | ... | feature_70 | LUMO
```

- **First column**: `Molecule`, an ionic-liquid cation identifier.
- **Middle columns**: numerical physicochemical features.
- **Final column**: `LUMO`, the regression target used to represent cation reductivity.
- **Molecule labels**: normalized readable examples include `P-(CH3)3, (CF3)`, `P-(CN)4`, and `S-(CH3)2, (CF3)`.

---

## 🔬 Method at a Glance

### 🧹 Descriptor selection

The feature-engineering notebook first controls descriptor redundancy, then ranks nonlinear descriptor contributions with Random Forest and SHAP, and finally performs iterative refinement based on predictive performance.

### 🧱 Ensemble modelling and interpretation

The tree-stacking notebook tunes the enabled regressors through Bayesian optimization and uses their out-of-fold predictions as inputs to a linear-SVR consensus model. R2 and RMSE summarize predictive performance. SHAP values from the base learners are combined according to their predictive fidelity across repeated data partitions.

## ⚙️ Environment and Dependency Audit

`requirements.txt` contains every non-standard package imported by the two notebooks, plus the JupyterLab runtime used to execute them.

| Status | Packages | Role |
|---|---|---|
| **Required** | `pandas`, `numpy`, `openpyxl` | tabular data and Excel I/O |
| **Required** | `scikit-learn`, `scikit-optimize` | regression, validation, preprocessing, SVR, and Bayesian search |
| **Required** | `xgboost`, `catboost`, `lightgbm` | enabled tree-regression candidates |
| **Required** | `shap`, `matplotlib`, `seaborn`, `tqdm` | explanation, visualization, and progress reporting |
| **Notebook runtime** | `jupyterlab`, `ipykernel` | interactive notebook execution |
| **Optional alternative** | `notebook==7.3.2` | install only when the Notebook interface is preferred over JupyterLab |
| **Not used here** | `umap-learn`, `ipywidgets` | omitted because neither notebook imports them |

`scipy` and other low-level packages are installed automatically as transitive dependencies of the required scientific stack; they do not need to be pinned separately for this release.
